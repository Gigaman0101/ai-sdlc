ยังเริ่ม review ไม่ได้ครับ เพราะผมหาไม่ได้ว่า "โค้ดที่เพิ่งแก้" คือไฟล์ไหน

- คุณไม่ได้ระบุไฟล์หรือโฟลเดอร์มา
- โปรเจกต์นี้ไม่ใช่ git repository (`git rev-parse --is-inside-work-tree` ได้ผล `fatal: not a git repository`) จึงใช้ `git diff` หาไฟล์ที่เปลี่ยนไม่ได้

ผมไม่อยาก review ทั้งโปรเจกต์ไปเลย เพราะจะช้ามาก และจุดที่คุณสนใจจะจมอยู่ในผลลัพธ์อื่นที่ไม่เกี่ยวข้อง

**ช่วยบอกหน่อยครับว่าแก้ไฟล์หรือโฟลเดอร์ไหนไป?** ตัวอย่างเช่น:
- `app/api/products/route.ts`
- `src/components/ProductGallery.tsx`
- ทั้งโฟลเดอร์ `app/products/`

พอได้รายการไฟล์แล้ว ผมจะรัน ESLint และ `tsc --noEmit` กับไฟล์เหล่านั้นก่อน (รวม `npx @google/design.md lint DESIGN.md` ถ้าแก้ `DESIGN.md` ด้วย) จากนั้นจะอ่านโค้ดเพื่อหาปัญหาด้าน logic, security และจุดที่ไม่ตรงกับ convention ของโปรเจกต์ แล้วสรุปเป็นรายงาน ผมจะไม่แก้ไฟล์ใดๆ เองครับ

เพิ่มเติม: ถ้ารัน `git init` แล้ว commit ไว้เป็น baseline ครั้งต่อไปผมจะหาไฟล์ที่เพิ่งแก้ได้เอง โดยคุณไม่ต้องบอก
